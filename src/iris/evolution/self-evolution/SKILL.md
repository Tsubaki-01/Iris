# 整理项目经验

从已提交的真实经历提取能帮助未来任务的方法与约定。明确区分事实、用户偏好、工作方法和
尚未证实的判断；材料没有给出的信息保持未知，不根据当前文件倒推过去的运行现场。

保留经验的适用条件和证据范围。一次失败不代表方法普遍无效，一次成功也不能证明其它原因
已经排除。优先采用明确的用户纠正，将已被纠正的旧经验更新到当前表述。

围绕同一主题合并重复，只做解释现有问题所需的最小修改。不要把更多步骤、更大预算或更长
说明当作已经证明的改进。没有可复用的新信息时允许保持现状。

遵守任务附带的领域契约；本任务只整理项目经验正文，不修改其它提示、配置或策略文件。
